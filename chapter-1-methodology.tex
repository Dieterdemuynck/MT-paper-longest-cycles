\section{Graph Generators}
\label{sec:generators}

Efficient but exhaustive graph generation is a difficult problem to solve. Writing a specialized graph generator specifically for this problem is expected to take the work of an entire master thesis as is\todo{source?}. When a graph generator has to generate a large magnitude of graphs, we want to only generate each graph once. In a nutshell, if we can rearrange a graph without removing or adding vertices or edges to get another graph, we call those graphs isomorphic. If not much care is put into generating each graph once, the same graph can easily be generated multiple times as isomorphic graphs, where for example simply the order of the nodes is different. Luckily, graph generation is an important field of research in computer sciences, and many graph generators have already been developed\todo{cite}\cite{article:jorik-jooken}, including some which we will use in this thesis.

\subsection{Nauty and GenerateUHG}

The \texttt{Nauty} package\todo{cite}\cite{lib:nauty} for example has a graph generator \texttt{geng} which can ``generate non-ismorphic very quickly''\cite{lib:nauty}, including specifically 2-connected graphs. It can also output its graphs in the \texttt{graph6} format, which is a compact ASCII string representation of graphs\todo{citation?}. This creates a useful graph generator for RQ\ref{rq1}.

During the year we realised that it is likely that most of the generated 2-connected graphs are hamiltonian. Since a hamiltonian graph has a cycle that goes through all vertices of the graph, this would mean that the intersection of all longest cycles would simply be all vertices. We would thus like to avoid hamiltonian graphs completely. This is why, for RQ\ref{rq1}, we instead opted to use the Uniquely Hamiltonian Graphs generator\todo{cite}\cite{lib:UHG}, which holds a program \texttt{GenerateUHG} that allows us to generate graphs with a specific amount of hamiltonian cycles, in the \texttt{graph6} format. By setting that amount to 0, we only get non-hamiltonian graphs, which we suspect to have a much lower quantity of graphs than simply 2-connected graphs.

Using this generator instead reintroduced the problem of making sure the graphs are 2-connected, since we could not add this condition to the generator's input. The \texttt{Nauty} package luckily also contains the program \texttt{pickg}, which lets us filter the output of another program. It takes \texttt{graph6} strings as input, and only outputs those strings for which the graph is 2-connected, given the correct parameters \todo{include parameters}. This program is very efficient compared to generation and the rest of the algorithm\todo{proof}, and therefore the use of \texttt{GenerateUHG} with \texttt{pickg} seems to be a good choice for the graph generation of RQ\ref{rq1}.

\section{Finding the Intersection of longest 11-cycles}
\label{sec:algorithms}

\subsection{Intersection of cycles}

To know if a graph has circumference 11 and has no vertex meeting every 11-cycle for RQ\ref{rq1}, we need an algorithm that can find the length of the longest cycle (the circumference) of the graph, while also keeping track of the intersection of all 11-cycles. Finding the circumference is an NP-hard problem\todo{cite, proofcheck}\cite{to-do}, meaning there is no known polynomial algorithm for it and is a difficult problem to solve. In this thesis, the best solution we have is to simply enumerate all cycles and find the longest. This also already provides an easy method for finding the intersection of all 11-cycles: if we find a cycle of length 11 during enumeration of all cycles, we can simply use its vertices to compute the intersection with all previous 11-cycles. Thus, we need an algorithm for enumerating all cycles efficiently.

\subsubsection{Enumeration of all cycles}

\todo{proofread}
The simplest approach to this problem is a depth-first search on the vertices. Simply take a starting vertex and set it as visited. Then take an unvisited edge for the last visited vertex (also setting this edge as visited), and consider the other vertex of that edge as a candidate next vertex. If this candidate is not yet visited, we simply add it to the currently visited vertices, and repeat the previous steps from this vertex. If during this process, the candidate is the original starting vertex, and there are at least three visited vertices, then we have found a cycle, and the vertices of the cycle are the visited vertices, and the length of the cycle is equal to the amount of visited vertices. If the candidate is not the original starting vertex, but has been visited, we can simply ignore it\todo{comparison with alternative algorithm}, and continue DFS from the previous vertex. Lastly, if the last visited vertex has no more unvisited edges, we can consider this vertex spent and pop it from the list of visited vertices, which also requires us to set its edges as unvisited again.

This algorithm has a glaring issue when it comes to efficiency, namely that during enumeration of the cycles, all cycles are enumerated as many times as it has vertices, times two. The algorithm takes every vertex of the cycle as a starting vertex, and discovers the cycle each time twice, in the two directions it can travel down the cycle. We can reduce this number by using a useful property of the way vertices of graphs are often represented in computer programs. In this thesis' source code, vertices are represented as simple integers, from 0 to $n-1$ with $n$ equal to the order of the graph. This adds the property that the vertices are ordered.

By considering the starting vertex as the ``minimal'' vertex of the DFS algorithm, only allowing vertices to be candidates if they are higher in order than this starting vertex, we can greatly reduce the search space of the algorithm for many starting vertices, while also guaranteeing we only discover each cycle twice, namely starting from its minimal vertex. We can reduce this further to discovering each cycle only once, by also defining an order on its second and last discovered vertex. By claiming we only consider a cycle when the second visited vertex is lower in order than the last visited vertex, we only discover each cycle in one of the two directions.

\subsubsection{Stopping enumeration early}

This algorithm allows us to enumerate all cycles of the graph exactly once. We can get an exact value of the circumference of the graph by setting the circumference equal to 0 at the start of the enumeration and, for each found cycle, taking the maximum of the current believed circumference and the length of the cycle. Note that we are only interested in the graphs with circumference 11 however. Luckily, this enumeration also allows us to stop early when a graph is found to have a cycle that is larger than 11, as we immediately know the graph to be uninteresting for RQ\ref{rq1}.

Similarly, we are also uninterested in cycles smaller than 11. We can choose the starting vertex as the smallest vertex not yet chosen as starting vertex (i.e. iterate through the starting vertices in order), beginning from the lowest ordered vertex.

Of course, we are also interested in the intersection of all 11-cycles. By setting the initial intersection equal to all vertices of the graph at the start of enumeration, whenever a cycle is detected that has length 11, we can take the intersection of the current known intersection of 11-cycles and this last 11-cycle. The result at the end of the enumeration will be the intersection of all 11-cycles if there are any, or all vertices otherwise. \begin{algorithmic}[1]
\Require Graph $G=(V,E)$ with ordered vertices, integer $k > 2$
\Ensure 
    Maximum cycle length $\textit{circumference}$ and
    intersection of all $k$-cycles $\textit{intersection}$

\State $\textit{circumference} \gets 0$
\State $\textit{intersection} \gets V(G)$

\State $m \gets |V(G)| - k$
\Comment{largest possible minimal vertex of a $k$-cycle}

\For{$i \gets 0$ to $m$}
    \State $\textit{visited} \gets \{i\}$
    \State $\textit{path} \gets [i]$
    \State $\textit{indices} \gets [0]$
    \Comment{next adjacency index for each depth}

    \While{$\textit{path} \neq \emptyset$}

        \If{$\textit{indices.back()} \geq |\Gamma(\textit{path.back()})|$}
            \Comment{all neighbors processed}
            \State remove last vertex from $\textit{visited}$
            \State pop last element from $\textit{path}$
            \State pop last element from $\textit{indices}$
            \If{$\textit{indices} \neq \emptyset$}
                \State increment $\textit{indices.back()}$
            \EndIf
            \State \textbf{continue}
        \EndIf

        \State $u \gets \textit{path.back()}$
        \State $v \gets \Gamma(u)[\textit{indices.back()}]$

        \If{$v \in \textit{visited}$ \textbf{or} $v < i$}

            \If{$v = i$}
                \Comment{cycle found}
                \State $\ell \gets |\textit{path}|$
                \State $\textit{circumference} \gets \max(\textit{circumference}, \ell)$

                \If{$\ell > k$}
                    \Comment{optional early stopping}
                    \State $\textit{intersection} \gets \textit{visited}$
                    \State \Return failure
                \EndIf

                \If{$\ell = k$}
                    \State $\textit{intersection} \gets
                        \textit{intersection} \cap \textit{visited}$
                \EndIf
            \EndIf

            \State increment $\textit{indices.back()}$
            \State \textbf{continue}
        \EndIf

        \Comment{extend DFS path}
        \State add $v$ to $\textit{visited}$
        \State append $v$ to $\textit{path}$
        \State append $0$ to $\textit{indices}$

    \EndWhile
\EndFor

\State \Return success
\end{algorithmic}
