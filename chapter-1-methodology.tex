\section{Graph Generators}
\label{sec:generators}

Efficient but exhaustive graph generation is a difficult problem to solve. A graph generator needs to be exhaustive (i.e. generate every graph in a certain category), while also avoiding generating isomorphic graphs. If not much care is put into generating each graph once, the same graph can easily be generated multiple times as isomorphic graphs, resulting in redundant computations. Many graph generators have already been made, each of which already took a lot of research\cite{article:jorik-jooken}. That is why, rather than making an attempt at our own graph generator specific for this problem, we use existing graph generators in this thesis.

\subsection{Nauty and GenerateUHG}

The \texttt{Nauty} package\cite{lib:nauty} has a graph generator \texttt{geng} which can ``generate non-ismorphic graphs very quickly''\cite{lib:nauty}, including specifically 2-connected graphs. It can also output its graphs in the \texttt{graph6} format, which is a compact ASCII string representation of graphs\todo{citation?}. This creates a useful graph generator for RQ\ref{rq1}.

During the year we realised that it is likely that most of the generated 2-connected graphs are hamiltonian, as seen in Table~\ref{tab:2con-nonhamil}.\todo{table with values} Since a hamiltonian graph has a cycle that goes through all vertices of the graph, this would mean that the intersection of all longest cycles would simply be all vertices. We would thus like to avoid hamiltonian graphs completely. This is why, for RQ\ref{rq1}, we instead opted to use the Uniquely Hamiltonian Graphs generator\cite{lib:UHG}, which holds a program \texttt{GenerateUHG} that allows us to generate graphs with a specific amount of hamiltonian cycles, in the \texttt{graph6} format. By setting that amount to 0, we only get non-hamiltonian graphs, which we suspect to have a much lower quantity of graphs than simply 2-connected graphs.

\subsection{plantri}

In the second research question RQ\ref{rq2}, only planar graphs are relevant, and as such, a planar graph generator seems to be the most interesting. The \texttt{plantri} package~\cite{lib:plantri} includes a suitable generator \texttt{plantri} for this. With the correct parameters, this package can generate 2-connected planar graphs with minimal degree 4. This generator only generates non-isomorphic 2-connected graphs where isomorphism is defined with reference to the embedding on a sphere, ``which means that outputs may be isomorphic as abstract graphs if the connectivity is less than 3''~\cite{lib:plantri}, i.e. there may be some duplicate 2-connected graphs. Despite this redundancy, generating planar graphs remains more efficient than generating 2-connected graphs and checking their planarity. 

It has also been shown that all 3-connected planar graphs, with minimal degree 4, on at most 22 vertices are hamiltonian~\cite{article:hamiltonian-planar}. This means that up to 22 vertices, we simply have to generate graphs with connectivity 2, i.e. graphs which are 2-connected but not 3-connected. This reduces the search space even more, as seen in Table~\ref{tab:2con-planar}.

The parameters used include the option \texttt{-p} to select general plane simple graphs, the option \texttt{-m4} to select graphs with minimal degree 4, the option \texttt{-c2x} to select exclusively 2-connected graphs and not 3-connected graphs. Lastly, the option \texttt{-g} is used which forces the outputted graphs to be in the \texttt{graph6} format.

\section{Finding the Intersection of longest 11-cycles}
\label{sec:algorithms}

\subsection{Intersection of cycles}

To know if a graph has circumference 11 and has no vertex meeting every 11-cycle for RQ\ref{rq1}, we need an algorithm that can find the length of the longest cycle (the circumference) of the graph, while also keeping track of the intersection of all 11-cycles. Finding the circumference for a 2-connected or planar graph is known to be an NP-hard problem~\cite{article:np-completeness}, meaning there is no known polynomial algorithm for it and is a difficult problem to solve. In this thesis, the approach used to compute the circumference of a graph is to enumerate all cycles and take the maximum of the length of these cycles. This also already provides an easy method for finding the intersection of all 11-cycles: if we find a cycle of length 11 during enumeration of all cycles, we can simply use its vertices to compute the intersection with all previous 11-cycles. Thus, we need an algorithm for enumerating all cycles efficiently.

\subsubsection{Enumeration of all cycles}

The simplest approach to this problem is a depth-first search on the vertices. Simply take a starting vertex and set it as visited. Then take an unvisited edge for the last visited vertex (also setting this edge as visited), and consider the other vertex of that edge as a candidate next vertex. If this candidate is not yet visited, we simply add it to the currently visited vertices, and repeat the previous steps from this vertex. If during this process, the candidate is the original starting vertex, and there are at least three visited vertices, then we have found a cycle, and the vertices of the cycle are the visited vertices, with the length of the cycle equal to the amount of visited vertices. If the candidate is not the original starting vertex, but has been visited, we can simply ignore it, and continue DFS from the previous vertex. Lastly, if the last visited vertex has no more unvisited edges, we can consider this vertex spent and pop it from the list of visited vertices, which also requires us to set its edges as unvisited again.

This algorithm by itself is not yet efficient: during enumeration of the cycles, each cycle is found once for every vertex it contains, times two. The algorithm takes every vertex of the cycle as a starting vertex, and discovers the cycle each time twice, in the two directions it can travel down the cycle. We can reduce this number by using a useful property of the way vertices of graphs are often represented in computer programs. In this thesis' source code, vertices are represented as integers, from 0 to $n-1$ with $n$ equal to the order of the graph. This provides us with the useful property that the vertices are ordered.

By considering the starting vertex as the ``minimal'' vertex of the DFS algorithm, only allowing new vertices to be candidates if they are higher in order than this starting vertex, we can greatly reduce the search space of the algorithm for many starting vertices, all while guaranteeing we only enumerate each cycle twice. We can reduce this further by also defining an order on its second and last discovered vertex: by only outputting a cycle when the second visited vertex is lower in order than the last visited vertex, we only enumerate each cycle when it was travelled one of the two directions.

\subsubsection{Halting cycle enumeration early}

This algorithm allows us to enumerate all cycles of the graph exactly once, under the assumption the graph is connected. We can get an exact value of the circumference of the graph by setting the circumference equal to 0 at the start of the enumeration and, for each found cycle, taking the maximum of the current believed circumference and the length of the cycle. Note that for RQ\ref{rq1} we are only interested in the graphs with circumference 11. As a result, we can halt enumeration of the cycles early when a graph is found to have a cycle that is larger than 11, as said graph is no longer relevant for RQ\ref{rq1}.

Additionally, cycles that are smaller than 11 are also uninteresting. If no 11-cycle or larger is found, then the circumference of the graph is lower than 11, and again not relevant for RQ\ref{rq1}. Therefore, we can safely reduce the number of starting vertices, by skipping the 10 highest ordered nodes, as running DFS with these as minimal vertices can only result in cycles of length 10 or smaller.

During enumeration, we must also compute the intersection of all 11-cycles. Set the initial intersection $I$ equal to all vertices of the graph $V(G)$ at the start of enumeration. Whenever an 11-cycle is enumerated, set $I$ equal to the intersection of $I$ and the vertices of the 11-cycle. The result at the end of the enumeration will be the intersection of all 11-cycles if there are any, or all vertices otherwise. If there are no 11-cycles, then the computed circumference is smaller than 11 (or larger if computation halted early due to a larger cycle), and therefore irrelevant for RQ\ref{rq1}.

        \If{last vertex in \textit{visited} has run through all neighbors}

            \State remove last element from $\textit{indices}$
            \If{\textit{indices} not empty}

\subsection{Construction by C. T. Zamfirescu}
\label{sec:tube-graph}

C. T. Zamfirescu showed~\cite{article:zamfirescu} that for every pair of integers $\ell \ge 2$ and $p \ge 4$, there exists a 2-connected graph G of order $\ell p$ and circumference $(\ell+1) (p-1) + 1$ whose intersection of all longest cycles is empty. We repeat the construction of the graph $G$ used in the proof here. Note that in this thesis, we use a different convention for $\ell$ than in the paper by C. Zamfirescu.
Take two cycles $(a_0, a_1, ..., a_{p-1})$ and $(b_0, b_1, ..., b_{p-1})$, each of length $p$, and connect $(a_i, b_i)$ for all $i$. Then, insert vertices on each edge $(a_i, b_i)$ until each becomes a path of length $\ell$ (i.e., has $\ell$ edges or $\ell-1$ vertices, including the vertices $a_i$ and $b_i$). Denote these paths from $a_i$ to $b_i$ as $H_i$. If $p$ is even, remove the edges $a_{p-1}a_0$ and $b_{p-1}b_0$, and replace them with the edges $a_{p-1}b_0$ and $b_{p-1}a_0$. We denote the graph constructed in this way as $G_{p,ell}$. C. Zamfirescu has shown~\cite{article:zamfirescu} that the cycle $C$ with vertices

$$
\bigcup_{i \neq 0} V(H_i) \cup {b_0}
$$

and edges

$$
\bigcup_{i \neq 0} E(H_i)
  \cup {(a_j,a_{j+1})}_{j \text{odd}}
  \cup {(b_k,b_{k+1})}_{k>0 \text{even}}
  \cup \begin{cases}
    \emptyset\ \text{if}\ p \text{odd} \\
    (a_{p-1},b_0)\ \text{otherwise}
  \end{cases}
$$

is a longest cycle of the graph $G$ avoiding all vertices $v \in V(H_0) \setminus \{b_0\}$, and that a similar cycle can be constructed for all other vertices. Figure~\ref{fig:tube-graph-odd} shows the graph $G_{5,2}$ alongside one longest cycle in the graph, and similarly Figure~\ref{fig:tube-graph-even} shows the graph $G_{4,3}$ alongside one longest cycle.

\subsection{Studying the Gadget}
\label{sec:gadget}

The construction by C. T. Zamfirescu starts off from two identical cycles with respective vertices connected. This graph is then modified, resulting in graphs with the desired properties. Studying this base graph, which we call a gadget, and seeing what properties it has and how modifying it results in the desired graphs could lead to new insights as to how to modify it differently to find new results for RQ\ref{rq2}.

In this thesis, we look deeper into the types of cycles that can be created from this gadget, and how inserting vertices on their edges changes the length of these cycles. It is this approach that has led to new negative results to the question of RQ\ref{rq2}.

\subsection{Almost-solution to RQ1}

While a solution for RQ\ref{rq1} is unknown, we do have an upper bound for the smallest amount of vertices in the intersection of all 11-cycle. In \cite{article:zamfirescu}, a graph of circumference 11 is constructed in which all but one vertex avoid all longest 11-cycles. This graph exploits the properties of the Petersen's graph, which is a hypohamiltonian graph of order 10 and thus circumference 9, and extends the three edges incident on one of its vertices $v$ with one extra vertex each, as seen in Figure~\ref{fig:petersen-divided}. This extends all cycles through this vertex $v$ by either 1 or 2. One can prove that as a result, this new graph of order 13 has circumference 11, with only one vertex meeting every 11-cycle~\cite{article:zamfirescu}.
